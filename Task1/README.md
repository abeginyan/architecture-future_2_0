## Главные архитектурные решения

1. **Домены вместо одного DWH.** Клиники, ИИ-сервисы, финтех и головной офис владеют своими данными и логикой. Бизнес-логика возвращается из DWH в сервисы доменов.
2. **Отдельная платформа данных («витрина»).** Озеро данных, загрузка, трансформации, быстрые аналитические витрины, семантический слой, BI и портал самообслуживания. Отчёты строятся за секунды-минуты (сценарий S1).
3. **Медицинские данные в платформу не попадают.** Каждый домен публикует только разрешённые наборы (allow-list), загрузчик блокирует остальное (S4).
4. **Функции ESB распределены, а не заменены одной Kafka.** Kafka доставляет события, реестр схем проверяет формат, потоковая обработка преобразует и проверяет смысл, очередь ошибок и повторы дают надёжность, бизнес-логика уходит в сервисы доменов, API Gateway обслуживает запросы. Домены общаются по зафиксированным контрактам, поэтому финтех и ИИ развиваются независимо (S2). Путь миграции: [esb_migration.md](esb_migration.md).
5. **Шаблон домена для новых бизнесов.** Фарма и электроника подключаются по стандарту: события в Kafka и data product в платформу, без правок в DWH (S3).
6. **Единая безопасность.** SSO, роли и атрибуты доступа, фильтрация строк, каталог данных, журнал доступа (S4).
7. **Облако и надёжность.** Мультизона, резервное копирование, репликация критичных БД (S5).
8. **Плавный переход.** Аналитическая часть старого DWH переводится в «только чтение», а клинический контур легаси (PowerBuilder и данные, в которые клиники пишут приёмы и медкарты) продолжает работать с записью, пока не выполнены условия отключения ([clinical_contour.md](clinical_contour.md)). Camel работает как мост в Kafka, потоки переводятся по одному (параллельный запуск, сверка, переключение, откат), затем Camel и DWH отключаются.

## Метки сценариев на диаграмме

S1 — быстрая отчётность · S2 — независимое развитие финтеха и ИИ · S3 — масштабирование на новые бизнесы · S4 — безопасность и регуляторы · S5 — надёжность и доступность

## Как пересобрать диаграмму

```bash
java -DPLANTUML_LIMIT_SIZE=16384 -jar plantuml.jar -tpng C4_Container.puml
```

Параметр `PLANTUML_LIMIT_SIZE` нужен, потому что диаграмма шире стандартного лимита 4096 px.
