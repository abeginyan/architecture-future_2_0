# Задание 3. Технологический радар «Будущее 2.0»

Картинка: [tech_radar.png](tech_radar.png). Таблица ниже собрана из того же списка, что и картинка (номера совпадают); скрипт для пересборки: [build_radar.py](build_radar.py).

## Как читать радар

| Кольцо | Значение |
|--------|----------|
| **Adopt** | внедряем сейчас |
| **Trial** | пилот в первых доменах |
| **Assess** | изучаем |
| **Hold** | новое не начинаем, выводим |

| Цвет точки | Статус |
|------------|--------|
| Синий | Новая технология или практика (предлагаем) |
| Зелёный | Текущая технология, сохраняем |
| Красный | Текущая технология, выводим из эксплуатации |

## Бизнес-сценарии (метки те же, что в Заданиях 1 и 2)

| Метка | Сценарий |
|-------|----------|
| **S1** | Быстрая подготовка отчётности |
| **S2** | Независимое развитие финтех- и ИИ-направлений |
| **S3** | Масштабирование: подключение новых бизнесов |
| **S4** | Безопасность и соответствие требованиям регуляторов |
| **S5** | Надёжность и доступность сервисов |

## Что чем заменяется

| Сейчас (Hold) | Приходит на смену | Зачем |
|---------------|-------------------|-------|
| MS SQL Server 2008 (DWH) | Lakehouse (Iceberg) + ClickHouse + базы доменов | Масштаб, скорость отчётов, поддержка и безопасность |
| Логика в хранимых процедурах и T-SQL | Сервисы доменов + dbt (аналитическая логика в коде) | Независимые релизы, тесты, переносимость |
| Apache Camel ESB | Kafka + API Gateway (Camel только как переходный адаптер) | Нет единой точки отказа, масштабирование |
| Power BI поверх DWH | BI на семантическом слое + портал самообслуживания | Единые метрики, отчёты без очереди в IT |
| PowerBuilder | Веб-интерфейс клиник (TypeScript + React) | Современный стек, переезд в облако; замена по этапам, после основной части изменений |

## Принятые допущения

- Конкретные продукты (Kong или Envoy, Superset или Power BI Service, облачный провайдер) указаны как кандидаты; окончательный выбор делается на этапе 1 по требованиям регулятора, стоимости и компетенциям команд.
- Позиции в кольце Assess не входят в план на год и пересматриваются на этапах 3–4.
- Радар пересматривается раз в квартал: позиции могут переходить между кольцами.
